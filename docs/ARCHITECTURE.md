# 구조와 결정

## 구성

React + TypeScript / Next.js App Router → 같은 출처의 `/api/v1/*` → 입력·세션·역할 검증 → 도메인 서비스 → 저장소 어댑터.

Sites의 React 스타터에서 시작하며, AWS·Vercel 이식이 쉬운 표준 Next.js 실행 경로를 기본으로 둡니다. 원본 Sites 관련 파일은 별도로 유지합니다. 이번 작업에서는 Sites 호스팅에 등록하거나 게시하지 않습니다.

- `app/`: 화면·API 진입점. API는 Node 런타임.
- `components/fitness/`: 모바일/PC 공통 제품 컴포넌트.
- `lib/domain/`: 데이터 타입, 가상 초기 자료, 루틴·인증·경험치·랭킹 규칙. UI와 독립적.
- `lib/server/`: 검증·세션·서비스·저장소. 브라우저로 내보내지 않음.
- `db/`: PostgreSQL 마이그레이션·적용 안내.
- `tests/`: 업무 규칙과 권한의 의미 있는 회귀 검사.
- `docs/`: 진행·데이터 계약·API·운영 기록.

## 저장소

기본은 서버의 로컬 JSON 저장소입니다. 단일 Node 프로세스 내 요청은 직렬화하고 임시 파일을 원자적으로 교체해 저장합니다. 브라우저 localStorage를 업무 데이터 저장소로 사용하지 않습니다. DB 연결 후 PostgreSQL 저장소가 같은 계약을 구현합니다. Vercel에는 로컬 파일 저장소를 배포하지 않습니다.

PostgreSQL은 사용자·목표·회차·수행/측정·인증·경험치·감사 기록을 분리합니다. 첫 시제품의 트랜잭션은 전체 상태 잠금 방식이므로 소규모 시범에 맞습니다. 실제 규모 확장 전에는 행 단위 쿼리·페이지네이션·잠금으로 분리합니다.

## 인증과 구분

로컬 데모 역할 전환은 실제 로그인으로 표시하지 않습니다. 운영용 API에는 JWT issuer·audience·JWKS 검증 지점을 둡니다. 실제 로그인 제공자와 조직 권한 매핑은 D2/R2의 연동 작업입니다. 인증자 권한은 서버에서 확인하며 클라이언트가 전달한 역할을 믿지 않습니다.

`performance`는 운동 수행 확인, `measurement`는 조건을 갖춘 측정 확인, `official`은 별도 공식 검정 결과입니다. 일반 관리자의 수행 승인을 공식 결과로 승격하지 않습니다. 측정 랭킹은 승인된 measurement만 사용합니다.

## 루틴

결정적인 규칙 기반 엔진을 우선 사용합니다. 목표, 확보 시간, 가능 요일, 최근 승인된 수행, 회복 상태를 입력받고 버전·이유를 보관합니다. 통증에는 강도 상승을 차단하고 다음 회차를 확인/회복 상태로 바꿉니다. 미승인 운동은 증량 근거가 되지 않습니다. 전문가 승인된 자료가 없으므로 실서비스 운동 처방은 아직 지원하지 않습니다.
