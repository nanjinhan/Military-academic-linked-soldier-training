5. R2에서는 실제 로그인 UI·토큰 세션·사용자 등록을 연결하고, 선택한 호스팅에 배포해 전체 흐름을 다시 확인합니다.

## 남아 있는 범위와 제한

- 운동 수치·XP·등급은 데모 규칙입니다. 전문 검토된 운동 처방이나 군 공식 평가 산식으로 확인되지 않았습니다.
- PostgreSQL 연결 코드는 작성했으나 실제 DB에 적용하지 않았습니다. 현재 어댑터는 전체 상태를 잠그는 소규모 시범 구조이며 운영 규모에 맞는 쿼리·페이지네이션이 필요합니다.
- 실제 인증 제공자·밀리패스·사진 업로드·푸시·외부 생성형 AI·네이티브 앱은 연결하지 않았습니다.
- 인증을 취소한 수행 회차의 재인증 정책·화면은 후속입니다. 보완 요청에 대한 재제출은 구현했습니다.
- 요청 속도 제한, 실제 자료 보관·파기, 운영 관측·복구, 실제 배포는 R2에서 마무리합니다. Docker 이미지 실행도 아직 검증하지 않았습니다.
- 현재 로컬 시연 데이터에는 9/28 가상 수행 1건과 9/29 가상 부분 수행 1건의 승인, 목표 변경이 남아 있습니다. 소스 압축에는 로컬 데이터·비밀키를 포함하지 않습니다.
- 운동 화면의 세트 체크·타이머는 화면을 닫으면 초기화됩니다. 인증 입력 화면에서 제출해야 기록이 저장되며, 세트별 내용은 수정 가능한 수행 메모에 포함됩니다.

## 검증 증거

`VALIDATION.md`에 자동 검사와 브라우저 확인 내용을 기록했습니다. 최초 구현에서 수행 제출 → 관리자 승인 → XP 600→680, U3에서 세트 체크 → 가상 부분 수행 제출 → 승인 → XP 680→720을 확인했습니다. 역할·소속 차단, 일괄 처리 원자성, 통증 우선, 취소 재계산은 자동 검사에 포함됩니다.

주요 파일: `components/fitness/` 화면, `lib/domain/` 업무 규칙, `lib/server/` API 서비스·세션·저장소, `app/api/v1/[...path]/route.ts` API 경로, `db/001_initial.sql` DB 구조, `tests/` 검증.
